# 口径与阈值

这些规则决定了命令为什么这样排序、这样打标签。用户质疑结果时，用这里的定义解释；要调整就改 `scripts/intel.mjs` 里对应的常量。

---

## 1. 三个 AI 字段的语义

| 字段 | 取值 | 语义 | 常见误解 |
| --- | --- | --- | --- |
| `relevance` | 0–100 | **与监控领域的相关度**，与内容真假无关 | 传闻只要切题也可以高分 |
| `importance` | `low/medium/high/urgent` | 影响范围 + 时效性 | 相关度高不等于重要 |
| `isReal` | `true/false/null` | 是否可核实（标题党、无来源、旧闻翻炒记 false） | 和 `relevance` 相互独立 |
| `aiStatus` | `pending/analyzed/heuristic/failed` | 研判是否完成、是否走了降级 | `heuristic` 表示**没有调用大模型** |

`aiStatus=heuristic` 的分数来自规则（标题党词计数、来源缺失、摘要长度），与模型结论不可混为一谈，回答时必须标注。

## 2. 「有效时间」

所有时间窗口（`--hours/--days/--from/--to`）与统计口径都使用：

```
有效时间 = published_at 非空 ? published_at : created_at
```

因此「关键词页显示 48h 有 5 条」与「跳到热点流后 total=5」必然一致；没有发布时间的官方文档页会被 `--dated` 排除。

## 3. 综合推荐分（`--sort recommended`）

由服务端 SQL 实时计算，不落库：

```
等级（urgent 100 / high 70 / medium 40 / low 15 / 未评 25）× 0.4
+ relevance × 0.3
+ 48h 新鲜度（线性衰减）× 20
+ 热度分档（≥1000→10、≥300→8、≥100→6、≥30→4、>0→2）
− isReal=false 25
− aiStatus=pending/failed 15
```

含意：**重要 × 相关 × 新鲜 × 热度，并扣掉存疑与未研判**。`brief` 默认用它，所以「值得写」不等于「最新」。

## 4. verify 的置信度规则

| confidence | 条件 | 建议语气 |
| --- | --- | --- |
| `high` | `isReal=true` **且** `aiStatus=analyzed` **且** 去重后来源 ≥ 2 | 可作为选题素材，写作时引用原文 |
| `medium` | `isReal=true` 且（`analyzed` 或 `heuristic`），但来源只有 1 个 | 先打开原文确认细节 |
| `low` | `isReal=false` / `isReal=null` / `pending` / `failed` | 不建议直接写，需人工核实 |

「来源数」= 目标条目自身来源 + `sameEvent` 里各条的来源去重计数。

## 5. 同事件相似度阈值

- 算法与后端去重一致：标题归一化（NFKC、小写、去标点）后取字符二元组，算 Dice 系数。
- 去重阈值 **0.86**（同一篇稿子）；本 skill 找「同事件」默认 **0.62**，可用 `--same-event` 覆盖。
- **已知局限**：中文媒体改写幅度大时相似度可能只有 0.3–0.5（实测「算力承压：曝 DeepSeek 实施限额」vs「DeepSeek 算力吃紧：长对话全面受限」= 0.33）。因此：
  - 默认 0.62 偏保守，宁可漏、不愿把不同事件合并；
  - **核实中文转载时建议 `--same-event 0.3`** 再跑一次，把两次结果都呈现给用户；
  - 不要为了命中更多而把默认值调得过低，否则会把「同公司不同事件」误判成同一事件。

## 6. audit 的健康标签

按优先级自上而下判定：

| 标签 | 条件 | 建议动作 |
| --- | --- | --- |
| `未扫描` | `lastCheckedAt` 为空 | 先跑一次采集 |
| `无产出` | `total = 0` | 换更具体的词 / 补范围限定 |
| `低产` | 近 7 天 ≤ 2 条 | 考虑换词或停用，避免占用采集配额 |
| `过宽` | 近 7 天 ≥ 10 条 **且** 平均相关度 < 45 | 加范围限定收窄 |
| `高产` | 近 7 天 ≥ 15 条 **且** 平均相关度 ≥ 55 | 优先巡检该词 |
| `健康` | 其余 | — |

**重复词判定**：归一化后完全相同，或一个词的 token 是另一个词的前缀（`DeepSeek` ⊂ `DeepSeek V4.1`）。刻意不用「包含」判断，避免 `Agent` 与 `Agentic Coding` 这类误报；中文连写（如 `DeepSeek大模型`）可能漏判，需人工确认。
