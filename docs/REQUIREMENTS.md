## 1. 背景与问题

使用者是 AI 编程博主，需要在热点出现后的第一时间完成“发现 → 判断 → 写作”。

现状的三个痛点：

1. **人工搜索滞后**：等信息流推送再动手，往往已经落后半天。
2. **抓到的内容很老**：通用网页搜索偏官网、文档页与常青页，缺少真正的“今天发生了什么”。
3. **真假与价值判断耗时**：同一事件被多家转载，标题党与旧闻混杂，逐条核实成本高。

因此产品目标不是“大而全的舆情系统”，而是**一条窄而快的情报流水线**：只盯几个关键词，只收最近 48 小时，只推值得写的那几条。

## 2. 目标与范围

**目标**

- 关键词命中后 30 分钟内完成一轮采集与研判。
- 默认只呈现有发布时间、且在时效窗口内的信号。
- 每条热点都给出可解释的可信度、相关性与一句话摘要。
- 桌面与移动端都能在 1 屏内看到“现在最值得关注的 3 条”。

**范围内**

关键词管理、多源采集、时效过滤、去重、AI 研判、WebSocket 推送、SMTP 邮件、通知历史、四页控制台、Agent Skill。

**范围外**

多租户与账号体系、云端部署编排、模型训练/微调、X 写操作、评论抓取、付费新闻 API。

## 3. 用户与场景

| 场景 | 触发 | 期望 |
| --- | --- | --- |
| 早间巡检 | 打开指挥台 | 30 秒内看清昨夜今晨的高优先信号 |
| 选题前检索 | 输入临时关键词 | 即时抓取一轮，按发布时间倒序查看 |
| 突发核实 | 收到浏览器/邮件通知 | 打开详情看判定依据与原文，判断能否开写 |

## 4. 功能需求

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 | 现状 |
| --- | --- | --- |
| 首屏加载 | < 3s（本机） | JS 461.8KB（gzip 150.2KB）、CSS 63.5KB（gzip 13.7KB） |
| API 响应 | < 1s | 本机统计/列表接口 0–4ms |
| 单轮采集 | 3 个关键词内 < 60s | Bing 串行限速，其余源并行 |
| 前端刷新 | 20s 轮询 + WS 事件即时刷新 | 已实现 |

### 5.2 数据质量与时效

- 所有信号入库前必须经过：发布时间解析 → 时效判断 → URL 指纹 → 标题相似度。
- 时效窗口按源区分（见第 6 节），可通过 `.env` 调整。
- 无发布时间的条目允许入库，但默认排序靠后且可一键隐藏，避免“旧闻冒充新讯”。
- AI 降级结果必须标记为 `heuristic`，不得伪装成大模型结论。

### 5.3 可访问性与可用性

| 约束 | 要求 |
| --- | --- |
| 文本对比度 | 正文 ≥ 4.5:1（当前最低 5.23:1，面板内） |
| 字号 | 正文 ≥ 12px；微标签 ≥ 9.5px 且高对比 |
| 触控目标 | 移动端主要按钮 ≥ 44×44px，筛选 chip ≥ 38px |
| 键盘 | 所有可交互元素有可见焦点环；走马灯可聚焦暂停 |
| 动效 | 尊重 `prefers-reduced-motion`，关闭时展示静态终态 |
| 布局 | 任意宽度无横向滚动；触屏无 hover 也能看到操作入口 |

### 5.4 安全与隐私

- 密钥只存 `.env`（已 gitignore），接口仅返回布尔能力标记。
- 输入校验：关键词长度、邮箱格式、枚举值、分页上限。
- SQL 全参数化；设置只允许白名单键写入。
- 邮件仅发送给配置的收件人，不做批量订阅。

### 5.5 可靠性

- 7×24 单进程运行；采集互斥锁避免定时与手动并发。
- 单一数据文件 `server/data/hotmonitor.db`，备份即复制。
- 单个数据源失败不影响其他源；错误写入 `runs.error` 并在设置页可见。

## 6. 数据源规格

| 源 | 接口 | 鉴权 | 默认时效 | 定位 |
| --- | --- | --- | --- | --- |
| Bing | `bing.com/search`（HTML） | 无 | 48h | 中文资讯覆盖面，需 `mkt=zh-CN` |
| Hacker News | Algolia `search_by_date` | 无 | 48h | 开发者圈最快信号 |
| arXiv | `export.arxiv.org/api/query` | 无 | 168h | 论文/算法层新进展 |
| GDELT | DOC 2.0 `artlist` | 无 | 48h | 全球新闻索引，约 15 分钟更新 |
| HuggingFace | `huggingface.co/api/models` | 无 | 336h | 模型上新，默认关闭 |
| X / Twitter | twitterapi.io `advanced_search` | `TWITTERAPI_KEY` | 48h | 意见领袖动态，可选 |

**采集约束**

- 关键词间间隔 ≥ 3s（默认 6s）；单关键词单源 ≤ 8 条。
- 每轮最多 10 个关键词、12 条新热点进入 AI 研判。
- GDELT 免费接口限流严格，按 10s 串行并 429 重试。
- Bing 使用 4 组 UA 轮换；命中验证码直接失败并记录。
- 导航型结果（官网首页、应用商店、百科）在解析层过滤。

## 7. AI 研判规格

**默认模型**

```ini
OPENROUTER_MODEL=deepseek/deepseek-v4.1-flash-1017
OPENROUTER_FALLBACK_MODEL=moonshotai/kimi-k3
```

> 当前出口区域对 OpenAI / Anthropic / Gemini 返回 403，故默认使用 DeepSeek + Kimi；网络环境变化后只改 `.env` 即可切回。

**输出 Schema（strict）**

```json
{
  "isReal": true,
  "relevance": 0,
  "importance": "low | medium | high | urgent",
  "summary": "50 字以内中文事实摘要",
  "reason": "一句话真假判断依据"
}
```

**降级链**：主模型 → 备用模型 → 启发式（`ai_status=heuristic`，UI 显示 `H` 角标）。

**边界**：模型无实时检索能力，真假判断基于来源、时间与文本特征，不能替代人工核实；结论必须带上判定依据。

## 8. 产品形态与视觉

**页面结构**

1. 指挥台：Hero + 优先队列 + 5 格指标 + 7 日曲线 + 可信度仪表 + 来源环图 + 实时流 + 系统状态。
2. 热点流：四维筛选 + 排序 + 时效开关 + 卡片流 + 详情抽屉。
3. 关键词：终端风格录入、逐行启停/编辑/删除/单关键词扫描。
4. 设置：通知通道、采集策略、AI 引擎与能力矩阵、通知历史。

**视觉语言（SIGNAL DESK）**

- 底色 `#08090b`，信号橙 `#ff5c1a`，酸性绿 `#c6ff3d`，琥珀 `#ffb020`，告警红 `#ff3b5c`。
- 字体：Space Grotesk（标题）+ JetBrains Mono（数据）。
- 元素：顶部指挥栏、信号走马灯、编辑部式大标题、聚光灯卡片、Hero 光束。
- 动效只服务信息层级：新信号入场、悬停高亮、扫描态；不做全站循环动画。

**响应式断点**：≥1240 双栏 Hero + 三栏 Bento；≤1040 单栏；≤880 顶栏导航收起、底部固定导航；≤560 进一步压缩。

## 9. 接口契约（摘要）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/keywords` | 关键词列表 |
| POST | `/api/keywords` | 新增，重复 409 |
| PUT | `/api/keywords/:id` | 改名/范围/启停 |
| DELETE | `/api/keywords/:id` | 删除，历史热点保留 |
| GET | `/api/hotspots` | `limit/offset/importance/source/isReal/status/keyword/q/days/dated/sort` |
| GET | `/api/hotspots/:id` | 详情 |
| POST | `/api/hotspots/search` | 即时抓取 `{term, domain?, analyze?}` |
| POST | `/api/hotspots/:id/analyze` | 单条重新研判 |
| GET / PUT | `/api/settings` | 设置读取/白名单更新（不含密钥） |
| POST | `/api/settings/test-email` | SMTP 自检 |
| GET | `/api/notifications` | 通知历史 |
| GET | `/api/stats` | 统计聚合（等级/来源/7 日趋势） |
| GET | `/api/runs` | 采集历史 |
| POST | `/api/collect` | 手动触发一轮 |
| POST | `/api/analyze-pending` | 补研判积压 |

**WebSocket 事件**：`connected`、`hotspot:new`、`hotspot:update`、`stats:update`、`run:update`、`notification`、`presence`。
